# HAIPipe baseline for DPPBench

This implementation preserves HAIPipe's AIPipe pretraining, frozen target-task
inference, HAI enumeration, and active-learning selection.  DPPBench's shared
operator space and YAML/DAG executor replace the upstream notebook runtime.

## Method mapping

| HAIPipe concept | DPPBench implementation |
|---|---|
| HI-pipeline | The task's human-authored `prepare.yaml` |
| AI-pipeline | Cross-task pretrained logical + component DQNs |
| HAI-pipeline | Ordered-subset insertion enumeration over the HI DAG |
| Candidate selection | HAIPipe alternative evaluator and iterative AL |
| Legality | `finalize_pipeline(...)` and `check_pipeline(...)` |

Target-task online DQN training is intentionally disabled.  Inference requires
compatible AIPipe and alternative-evaluator checkpoints.  Because DPPBench's
operator vocabulary differs from upstream HAIPipe, the published upstream
weights cannot be loaded and must be regenerated by cross-task pretraining.

## Common API usage

The implementation relies on shared APIs for all executable details:

- `get_data_ctx(...)`
- `get_available_ops(...)`
- `get_category_order(...)`
- `make_step(...)`
- `finalize_pipeline(...)`
- `check_pipeline(...)`
- `SearchPipelineEvaluator(...)`

It does not maintain a private operator catalog or private parameter factory.

## Files

- `haipipe.py`: top-level runner and output contract
- `hi_pipeline.py`: HI scaffold construction
- `operator_mapping.py`: HAIPipe components to DPPBench categories
- `env.py`: component-level AI-pipeline environment
- `trainer.py`: DQN training and greedy inference
- `combiner.py`: HI + AI enumeration/sampling and best candidate selection

## Cross-task pretraining

Pretraining is a separate phase and must receive an explicit training-task
split.  Do not include any target/test task in `--data_names`:

```bash
python scripts/pretrain_haipipe.py \
  --data_names <training tasks> \
  --held_out_data_names <target/test tasks> \
  --model <model> \
  --data_dir /mnt/sdb/dengjiale/dppbench/data \
  --output_dir /mnt/sdb/dengjiale/dppbench/output \
  --gpu_id <idle GPU>
```

The command writes `aipipe.pt` and `alternative_evaluator.pt` below
`<output_dir>/HAIPipe/pretrain/<model>/`.  Point `config.yaml` (or a run-specific
config) at those two files before target-task evaluation.  Pretraining is a
long-running GPU job and should normally be launched in tmux after checking the
selected GPU.
